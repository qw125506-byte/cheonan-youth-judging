# 2026년 천안시 청년정책 아이디어 공모전 심사결과 자동 집계 시스템

심사위원 6명 × 제안 14건(84건)의 심사표 점수를 입력하면, 제안마다 **최고점 1개·최저점 1개를 제외한 4명의 평균**으로 순위를 매기고 최우수 1·우수 2·장려 3을 선정합니다.

- 심사일: 2026. 10. 19.(월) 14:00~16:00, 천안시청 제2소회의실(7층)
- 초기 데이터: 「보고요지」의 심사위원 명단·심사 목록과 「제안심사표(안)」의 제안내용·심사요소·배점을 그대로 넣었습니다. **점수는 모두 미입력 상태**입니다.

## 바로 쓰기 (인터넷·설치 불필요)

`dist-single/index.html` 파일 하나만 있으면 됩니다. 심사 당일 PC에 복사한 뒤 **Chrome 또는 Edge로 더블클릭**해 엽니다.

- 입력한 점수는 그 PC의 그 브라우저에 자동 저장됩니다. 새로고침하거나 창을 닫았다 열어도 남아 있습니다.
- **입력하던 PC·브라우저를 바꾸면 데이터가 따라가지 않습니다.** 옮기려면 「⑤ 출력·백업 → 백업 파일(JSON) 내려받기」로 백업한 뒤, 새 PC에서 「백업 파일 불러오기」로 복원하세요.
- 브라우저의 ‘인터넷 사용 기록 삭제(쿠키 및 사이트 데이터)’를 하면 저장된 점수가 지워집니다. 심사 중간중간 JSON 백업을 받아 두세요.

| ④ 최종 순위·수상 | 순위·선정 등급, 수상 경계 동점 시 위원회 결정 기록, 결과 확정·확정 해제 |
| ⑤ 출력·백업 | 위원별 평가표·종합 집계표·최종 선정 결과표 인쇄/PDF, 엑셀·CSV, JSON 백업·복원, 초기화 |
| 설정·이력 | 실제/연습 모드 전환, 소수점 허용, 위원·제안 정보 수정, 수정 이력 |

### 키보드 입력
- 한 건씩 입력: `Enter`·`↓` 다음 항목, `↑` 이전 항목, `Esc` 입력 취소
- 14건 일괄입력: 종이 심사표 한 장을 한 행에 입력합니다. `Enter`로 오른쪽 칸, 행 끝에서는 다음 제안의 첫 칸으로 이동합니다
- **숫자를 누르는 즉시 자동 저장**됩니다(Enter를 누르지 않아도 됨). 화면 오른쪽 위에 마지막 저장 시각이 표시됩니다
- 한 칸에 이어서 입력한 내용은 수정 이력에 1건(변경 전 → 최종 값)으로 남습니다. `Esc`를 누르면 그 칸에 들어오기 전 값으로 돌아갑니다
- 잘못된 값(문자, 음수, 배점 초과, 허용하지 않은 소수점)은 그 칸을 미입력으로 두고 빨간 칸과 이유를 표시합니다
- 빈칸은 **미입력**으로 관리되며 0점으로 계산하지 않습니다

## 계산 규칙

```
최종점수 = (6명 점수 합계 − 최고점 1개 − 최저점 1개) ÷ 4
```

1. 최고·최저는 제안마다 따로 판정합니다.
2. 같은 최고점(최저점)이 여럿이어도 1개만 제외합니다. 6명이 모두 같은 점수면 서로 다른 두 위원의 점수가 제외되고 평균은 그 점수가 됩니다.
3. 6명이 모두 입력되어야 그 제안이 집계됩니다.
4. 내부 계산은 0.01점 단위 정수로 해서 부동소수 오차가 없습니다. 화면에는 소수 둘째 자리로 반올림해 보여 주고, 순위는 반올림 전 값으로 정합니다.
5. **최종 평균이 같으면** 다음 순서로 순위를 정합니다.
   - 1차: **실시가능성 합계**(위원 6명의 실시가능성 소계를 모두 더한 값)가 높은 순
   - 2차: 그래도 같으면 **효율성(경제성) 합계**(위원 6명 소계 합)가 높은 순
6. 두 기준까지 같으면 공동순위로 표시합니다. 그 동점이 **수상 등급 경계**(1|2위, 3|4위, 6|7위)에 걸치면 수상자를 자동으로 정하지 않습니다. 「④ 최종 순위·수상」에서 위원회가 정한 순서와 사유를 기록해야 확정할 수 있습니다. 총점 직접입력(세부점수 없음) 평가가 섞인 제안은 1·2차 기준을 계산할 수 없으므로 같은 방식으로 위원회 결정으로 넘어갑니다.
7. 84건이 모두 입력되고, 계산 검증을 통과하고, 경계 동점이 정리되어야 「심사결과 확정」을 누를 수 있습니다. 확정하면 점수가 잠기며, 풀려면 사유를 남겨야 합니다.

## 데이터 안전장치

- **실제 심사 데이터와 연습 데이터는 따로 저장**됩니다. 테스트 점수 자동 생성은 연습 모드에서만 할 수 있습니다. 연습 모드에서는 화면 맨 위에 주황색 띠가 보이고, 출력물과 파일 이름에도 ‘연습’이 표시됩니다.
- 모든 점수 입력·수정은 변경 전 값, 변경 후 값, 시각과 함께 수정 이력에 기록됩니다. 엑셀 ‘수정이력’ 시트로도 받을 수 있습니다.
- 백업 복원 시 파일 구조와 배점 범위를 검사합니다. 연습 백업은 실제 모드에 복원할 수 없습니다.
- 전체 초기화는 확인 창에 ‘초기화’를 입력해야 실행됩니다.

## 출력물

- **인쇄/PDF**: 인쇄 창에서 대상을 ‘PDF로 저장’으로 고르면 PDF가 됩니다. 시스템 글꼴(맑은 고딕)을 쓰므로 한글이 깨지지 않습니다. 위원별 평가표와 종합 집계표는 A4 가로, 최종 선정 결과표는 A4 세로 1쪽에 맞췄습니다.
- **엑셀(.xlsx)**: 위원별 원본 · 종합집계표 · 최종순위 · 수상자 · 계산검증 · 수정이력 6개 시트입니다. 종합집계표에는 엑셀 수식 `(SUM−MAX−MIN)/4`로 다시 계산한 열과 웹 결과와의 ‘일치’ 열이 있습니다.
- **CSV**: 종합집계표(엑셀에서 한글이 깨지지 않도록 UTF-8 BOM 포함)

## 이 버전의 한계

- 저장소가 브라우저 로컬 저장소라서 **여러 PC에서 동시에 입력하거나 실시간으로 공유할 수 없습니다.** 담당자 한 명이 종이 심사표를 받아 한 PC에서 입력하는 방식에 맞춰 만들었습니다.
- 심사위원별 로그인과 관리자 권한 분리는 서버가 필요하므로 이 버전에는 없습니다. 확정과 확정 해제는 화면 안의 확인 절차와 이력 기록으로 관리합니다.

## 개발자용

```bash
npm install
npm run dev          # 개발 서버
npm test             # 계산 로직·엑셀 내보내기 단위 테스트(34개)
npm run build        # dist/ (GitHub Pages 등 웹 서버용)
npm run build:single # dist-single/index.html (오프라인 단일 파일)
```

- React 19 + TypeScript + Vite 6 + Tailwind CSS 4, 엑셀은 SheetJS(xlsx 0.20.3)를 씁니다
- 계산 로직: `src/lib/calc.ts` (화면과 분리된 순수 함수), 테스트: `src/lib/*.test.ts`
- 초기 데이터: `src/lib/initialData.ts`

- 저장소: https://github.com/qw125506-byte/cheonan-youth-judging

코드를 고친 뒤 다시 배포하려면 아래 한 줄이면 됩니다. 테스트와 빌드를 거쳐 `dist/`를 `gh-pages` 브랜치에 올리고, 1~2분 뒤 웹 주소에 반영됩니다.

```bash
npm run deploy
```

소스 변경분은 평소처럼 `git add` → `git commit` → `git push`로 `main`에 올립니다. Pages 설정은 **Settings → Pages → Source: Deploy from a branch, `gh-pages` / `(root)`**입니다.

> 웹 주소로 열어도 점수는 **그 브라우저에만** 저장되고 GitHub로 전송되지 않습니다. 다른 사람이 같은 주소를 열면 빈 심사표가 보입니다.
